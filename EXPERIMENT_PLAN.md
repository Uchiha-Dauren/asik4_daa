# Experiment Design Card - recorded before the first run

Date: 2026-11-07. Seed: **20261107**. No benchmark has been run when this card is committed.

| Field | Plan |
| --- | --- |
| Questions | Edit distance: how does processed-state growth change with recursion versus DP, and can two rows reduce storage without changing the result? Search: when does KMP avoid the repeated comparisons of Naive search? |
| Sizes | All three edit algorithms: n = 2, 4, 6, 8, 10, 12, with m = n. Larger table/two-row experiments: n = 128, 256, 512, 1024, 2048, with m = n. Search: n = 10000, 20000, 40000, 80000, 160000; m = n/1000 = 10, 20, 40, 80, 160. All ranges span at least 4x. Recursion stops at n = 12 by design; this is a budget cap, not a claim about the machine's absolute limit. |
| Edit inputs and purpose | identical: the same seeded random string twice, showing the recursion's matching-character shortcut; random: two independently generated strings over a..z, showing a less regular workload; disjoint: a repeated n times versus b repeated n times, forcing every recursive mismatch to branch. DP fills the same number of cells for all three. |
| Search inputs and purpose | random: seeded random text over a..z, with a pattern copied from its middle, guaranteeing a match; first_mismatch: text a^n, pattern b^m, causing immediate rejection at every Naive alignment; near_match: text a^n, pattern a^(m-1)b, forcing m comparisons at every Naive alignment. Growing m with n exposes quadratic Naive work; this is a joint n,m experiment, not a fixed-pattern complexity claim. |
| Metrics | System.nanoTime elapsed time, reported as milliseconds per invocation and median of 5 measured runs. Edit: state_visits increments inside every recursive call, or each DP base/interior state evaluation; these units are related but not identical machine operations. Search: character comparisons, split into LPS preprocessing and search, with total as their sum. KMP timing includes building LPS. DP storage is a theoretical count of retained int slots, not measured heap/RSS. |
| Repetition | Deterministic batches keep short measurements above timer noise. Small DP: 2000 invocations/run; small recursion: 10000, 1000, 20, 2, 1, 1 for its six sizes. Large DP: max(1, 1000000/(n*n)); search: max(1, 160000/n). Two untimed batches precede 5 measured batches. Input generation, assertions and CSV writing are outside timing. Counter is reset on every invocation; CSV contains its per-invocation value and the batch size/time. |
| Predictions | Disjoint recursion grows exponentially; identical recursion visits n+1 states. DP evaluates (n+1)^2 states, so doubling n gives about 4x work, while two rows retain 2(n+1) integer slots instead of (n+1)^2. With m proportional to n, Naive near_match comparisons grow approximately quadratically and KMP comparisons approximately linearly. Both search methods should be near-linear on first_mismatch/random inputs; KMP is not guaranteed to have lower elapsed time there. |
| Plots | (1) Small edit state visits vs n on a logarithmic y-axis: where does repeated recursion appear? (2) Large DP median time vs n, plus theoretical int slots: what time/space tradeoff appears? (3) Search comparisons vs n for three input types: where does KMP save comparisons? (4) Search median time vs n: does measured time agree with the comparison trend? Every plot gets a title, labeled axes and a takeaway. |
| Reproducibility | The same Java command, seed and generator reproduce inputs, answers, batch sizes and counters. Wall-clock times vary with JIT, GC and hardware and cannot be exactly reproducible. Keep the original measured CSV and environment metadata. |

Plan changes: none at the time of registration. Any later change will be disclosed in REPORT.md.
